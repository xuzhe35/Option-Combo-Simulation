# CSV 导入回归验证记录（2026-09-14）

本记录只说明已验证的场景，不代表导入功能不存在其他缺陷。未操作真实账本或向券商发送任何请求。

> 公开版：原始报表的账号、文件名、持仓数量、现金金额和笔数均已脱敏为描述，验证方法与结论不变。

## 本次问题与修正

- 全年报表重建：旧逻辑在清空回放基线后仍跳过已有 CSV 引用。实际报表上精确复现了"只新增一部分、其余被跳过"的结果，以及随之而来的多条平仓超额告警。重建现在保留全部报表事件和由 Basis 还原的期初记录。
- 同秒追加：预览没有给新行分配顺序号，导致它们排在已有开仓之前。预览现遵循数据库的追加顺序。
- 重建异步请求：过期请求的失败曾能清除另一本账本或新模式的准备状态。现同时绑定账本、文件代次和请求代次；退回追加时重新解析。
- 遮罩账号：Activity 的遮罩账号（形如 `U***12345`）曾被当作完整账号直接比较，提前返回“读取 0 行”。现保留实际交易行数，明确提示账号需核实。只有可见部分匹配且用户确认当前文件归属，才会绑定完整账本账号。换文件、换账本、取消确认均使确认失效。不同完整账号、可见部分不匹配及缺失账号不能被此确认绕过。

> 以下原文件结果记录于 2026-09-14。2026-09-19 复核时旧 Dropbox 遮罩文件路径已不存在，该项不能重新执行；合成遮罩账户回归仍可运行。后续结果见 [09-19 记录](COST_BASIS_REVERSAL_REGRESSION_20260919.md) 与 [随机回归](COST_BASIS_RANDOMIZED_REGRESSION.md)。

## 两份实际文件的控制结果

### 全年累计报表（2026-01-01 至 2026-09-11，完整账号版）

- 写入记录 = 全部报表事件 + 1 条由 Basis 还原的期初记录。
- 回放无告警；期末股票与全部期权数量逐个与报表一致。
- 实际全年文件通过临时 SQLite 重建、同批重试和重复追加；另用独立小样本验证存档恢复。

### 遮罩账号日报（2026-09-11）

文件正文 Period 为 **2026-09-11 当天**。区间取自正文，不从文件名推断。

- Trades 段中，本标的的原始交易行合并为事件，股票交割行并入对应的指派事件，其他标的的行被排除；逐行核对无遗漏。
- 当日股票交割的增量小于期末持股，说明期初已有股票持仓，而本报表区间内看不到它的来源。
- 未确认遮罩账号时，按钮禁用且写入为零。
- 空账本或整本重建：仍阻断缺失的期初股票成本，没有生成虚构股票期初事件。
- 使用 **明确的测试基线**（股数等于上述期初差额、假设单价；该成本不是用户的真实成本）时：当日事件与 Basis 还原的期初期权事件可追加，实际数据库无告警。
- 独立核对原始 Proceeds + Comm/Fee 与当日事件现金；指派现金只含交割，不重复计算权利金。
- 期末数据库的股票和每个期权合约数量逐个与报表一致，其余期权归零。
- 同批重试及再次追加不新增重复记录；改为显示完整账号的同一报表也不重复。
- 测试基线比期初差额少 1 股时仍阻断，不自动填补差额。

3. 独立 Chrome：加载真实 HTML/CSS 和页面事件处理器，实际选择文件、勾选和撤销确认、切换追加/重建、点击提交及重选文件。HTTP 与后端请求全部拦截，不连接真实服务；断言提交的每条记录都绑定正确账号，且无页面脚本异常。
4. 全套 JavaScript：**1160 passed, 0 failed**；账本 Python：**258 passed, 1 skipped**。跳过项为依赖本机 IB bridge 模块的导入可用性检查，不能算作通过。
