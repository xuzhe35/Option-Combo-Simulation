# 成本账本：拆股与期权合约调整 CODE PLAN

> 日期：2026-09-23。状态：**待实施设计，不是已实现功能，也不是测试通过报告。**
>
> 目标：一份跨拆股的完整 TQQQ 股票＋期权报表可以正确导入；先拉 TWS、后补月报、重复导入、整本重建得到相同的持仓、现金和成本。证据不足时显示具体缺项并提供补齐入口，不能只留下“人工核对”四个字。
>
> 基线：当前工作区 schema v9。实施前重新核对版本和未提交改动；下文新增名称均为拟议接口。现行约束见 [账本设计](COST_BASIS_LEDGER_PAGE_PLAN.md)、[导入完整性](COST_BASIS_IMPORT_INTEGRITY.md)、[压力测试契约](STRESS_KERNEL_REFACTOR.md) 和 [随机回归](COST_BASIS_RANDOMIZED_REGRESSION.md)。

## 1. 现状与需要替换的假设

| 当前入口 | 已有行为 | 本次缺口 |
| --- | --- | --- |
| `cost_basis.html` 的手工 `split` | 输入比例，股票数量变化，现金与总成本保持 | 无完整的期权转换或报表公司行动处理 |
| `js/cost_basis_core.js::_applySplit` | 股数乘比例；未平期权产生 `split_crosses_open_option` | 原期权数量、条款和未实现权利金仍停在旧合约 |
| `js/cost_basis_import.js::_corporateActionProblems` | 本标的公司行动一律生成导入问题 | 不能将已明确的正常拆股变成可提交草稿 |
| `deriveOpeningPositions`、存根替换 | 基于交易变动和期末仓位推导期初 | 拆股不是普通加减；旧、新合约不能各自补一笔虚假开仓 |
| 前后端合约身份及时间线 | 主要按账户、C/P、行权价、到期日、乘数和券商身份分组 | 一次合法转换会跨越这些分组；不能仍只验证单个旧键 |
| `sharesPerContract` | 同时参与权利金、交割股数、身份、估值 | 非标准合约下，报价乘数与实际交割股数不一定相等 |
| TWS 单笔／批量对账 | 用真实成交解释数量差额 | 拆股调整不是成交，不能用虚假交易或期初存根填平 |
| What If、压力测试、卖方权利金统计 | 使用当前回放出的未平期权 | 必须接收拆股后的条款和承接权利金，不能继续估旧合约 |

现有“拆股跨越未平期权”告警已是提示项，不再阻断所有无关导入。这项修复保留；**去掉阻断不等于已经完成合约调整**。

## 2. 外部依据与产品范围

### 2.1 用真实规则约束设计

OCC 对 TQQQ 2025-11-20 的公告规定：合约张数乘 2，行权价按公告调整，报价金额乘数仍为 100，每张交割 100 股。公告列出的 `99.97 → 49.99` 也说明，不能只做二进制浮点除法，再凭默认精度猜新行权价。采用逐系列明确条款；公式只生成候选。[OCC #57592](https://infomemo.theocc.com/infomemos?number=57592)

2022-01-13 的 TQQQ 拆股也可作为另一份独立规则样例，不能把一个日期的规则当成该标的永久属性。[OCC #49829](https://infomemo.theocc.com/infomemos?number=49829)

IBKR Flex 的公司行动段可携带账户、资产类别、标的／合约身份、日期、数量、金额及交易引用；类型包括 Forward Split、Reverse Split、Contract Split 等。但这些字段不保证在每份导出中全部存在，也不等于提供了完整的新旧合约配对关系。[IBKR Corporate Actions](https://www.ibkrguides.com/reportingreference/reportguide/corporate%20actionsfq.htm)

以下数据结构、流程及验收规则是本项目的设计决策，不是对券商格式或所有公司行动的普遍假设。

### 2.2 本计划的交付范围

| 类型 | 应交付的结果 |
| --- | --- |
| 股票整数正向拆股，例如 2:1、3:1 | 报表识别、预览、数量／成本调整、追加与重建闭环 |
| 跨拆股的标准股票／ETF 期权 | 明确的新旧系列转换、权利金承接、后续开平仓／指派／行权／到期、TWS 对账与标准估值 |
| 连续多次拆股 | 按各自生效时点组合转换，历史查询能看到当时条款 |
| 股票非整数拆股、反向拆股 | 有理数比例；有证据的碎股保留或现金替代；不能四舍五入丢股 |
| 单一标的＋确定现金的调整期权 | 独立的报价／交割条款，真实交易与结算可入账，到期收益可算；缺乏支持的到期前估值明确停用 |
| 不明条款、待定现金、身份冲突 | 保存可继续处理的草稿，显示缺项；补齐后重建同一预览并一次提交 |
| 合并、分拆成多个证券、换股、跨币种篮子、FOP/FUT 公司行动 | 本轮不自动处理，逐项保留原因；不能误套股票拆股，也不能静默跳过 |

第一项单独上线不能宣称“跨拆股账本已经支持”。TQQQ 标准拆股至少完成阶段 P0–P6 的对应验收；非标准交割能力单列实际支持范围，不以泛化字段代替可用功能。

## 3. 不变式

1. 账本事件是事实来源。TWS 持仓只发现差异；查询公司行动或合约资料也只建立证据，不自动写账。
2. 拆股不是买卖，不产生新的权利金或成交佣金，也不把原未平期权的权利金提前实现。真实现金替代款另行记账。
3. 无现金的转换保持总现金、股票各成本口径的总成本、期权未实现权利金及累计已实现损益。每股／每张分摊可以变化。
4. 指派／行权现金只记录合约实际交割，开仓权利金不能再收付一次。
5. 原始成交数量、价格、券商引用和合约描述保留。只在生效边界转换当时仍未平的余额，不追溯改写成复权成交。
6. 一个公司行动的股票腿、全部期权转换腿及当时已知的附属调整是一个原子组；成功全部写入，失败全部回滚。
7. 重复、跨格式、跨月、TWS 重叠和重试不重复应用比例，不重新生成同一笔现金。
8. 新增缺陷只阻断受影响的本次操作；历史提示不重新变成全账本导入门禁。依赖未解决条款的计算不能显示“已完整核对”。
9. 每项输入、推导、人工确认、替代关系和来源都能在预览、流水及备份中追溯。

## 4. 数据模型与存储决策

### 4.1 新增复合事件，保留旧 split

新增 `kind=corporate_action`，本轮只接收 `actionType=split`。普通历史 `split` 保持原义和原记录；新入口统一生成新事件。一条复合事件保存明确的股票数量变动和期权转出／转入腿，不伪造 `option_trade`、平仓收益或期初余额。

建议在事件表增加版本化的 `corporate_action_json`、`contract_terms_json`、`effective_order_json`，并扩展种类 CHECK。JSON 必须经过字段、长度、枚举、数值和嵌套数量白名单校验，不能成为绕过校验的任意 payload。

| 字段 | 约束及用途 |
| --- | --- |
| `payloadVersion` | 明确版本；未知版本拒绝写入和恢复 |
| `actionKey` | 账户／账本范围内同一经济公司行动的稳定键；不使用本次文件摘要作身份 |
| `effectiveDate`、`effectiveAt`／`effectivePhase`、`timeZone` | 区分经济生效时点与报表记载日；保存原始时间及排序依据 |
| `ratioNumerator`、`ratioDenominator` | 约分后的正整数比，新股数／旧股数；限制范围并检查溢出 |
| `stockLeg` | 生效前数量、比例转换后数量、有符号增量、零现金；无股票持仓允许全部为 0 |
| `optionTransfers[]` | 每腿的旧／新条款引用、旧余额、转出增量、新数量及转入增量；保留转换链和来源 |
| `sourceEvidence[]` | 来源格式、原行引用／行号、内容摘要、券商事务引用、公告／人工条款依据及其版本 |
| `cashInLieuLinks[]` | 指向已确认现金替代款或待结算碎股权益，不能默认未知金额为 0 |
| `supersedesEventIds[]` | 显式修复旧手工拆股或重复调整；必须由后端逐项验证，不开放任意冲销 |

比例和规则用来检验显式转移腿。后端重放到生效前，逐项验证旧余额、比例和所有转移；不能只接受浏览器提交的“转换正确”标记。早期历史后来补入而改变边界余额时，需要重新解析该行动，不能静默使用旧数量。

另加来源引用表 `cost_basis_event_source_refs`（拟名），把一组公司行动的多个 Activity／Flex／券商子行引用绑定到同一事件，唯一约束包含账本和来源命名空间。同引用内容修订应报冲突；作废事件仍保留引用占用及替代链。

待补齐资料保存在独立的 `cost_basis_action_drafts`（拟名），绑定账本、文件摘要、读取时的账本版本及规则版本，不能混入事件表。保存草稿不改变经济账本或覆盖证明；恢复草稿必须重新核验，提交成功同事务标记已提交。草稿读写走既有访问限制和大小校验，备份中与已入账事件明确分开；删除账本时一并清理。

### 4.2 合约身份与条款分离

新增不可变、带生效区间的 `ContractTerms v2`：

- 券商身份：`conId`、`localSymbol`、`tradingClass`、标的身份、OPT 类型和币种；资料缺失时保留缺失，不能编造 conId。
- 可见条款：Call/Put、到期日、挂牌行权价及明确精度。
- `premiumMultiplier`：成交报价转成权利金金额的乘数。
- `exerciseAmountPerContract`：履约需交换的行权本金。
- `deliverableSharesPerContract`、`deliverableCashPerContract`：每张交割包，现金方向定义为“交割包包含的现金”，独立于行权本金。
- `termsVersion`／规范化摘要：精确标识条款；记录它属于哪个公司行动前后区间。

标准期权：报价乘数 100、交割 100 股、行权本金 `K × 100`、交割包现金 0。这只是标准条款的兼容映射，**不能自动套给疑似调整合约**。

旧 `sharesPerContract` 对未经调整的标准合约兼容读取；FOP/FUT 保持原口径。旧记录若已有非标准身份或跨拆股未解决提示，须保留“条款未核实”，不能迁移时宣布它是标准合约。

新旧合约是有方向、有生效时间的转换关系，不是永久相等的两个别名。身份解析要按当时条款版本工作，支持 conId 改变、保持不变、同可见条款但不同交割包，以及多个旧系列转入同一新系列。只有证明为同一目的系列才汇总；方向或来源不一致须报冲突。

### 4.3 现金替代与碎股

新增 `cash_in_lieu` 事件：关联公司行动、实际处置的碎股／权益数量、币种、净现金、费用及来源引用。它是经济处置，不是股息，也不是拆股比例本身产生的现金。

拆股日若券商继续保留可交易碎股，保留其精确数量；若已转为待现金结算权益，则单列该权益和分摊成本，不混入可交易股票对账。到账后按证据结清权益，现金及实现损益只计一次。短仓产生的应付现金同样保留符号。分摊沿用本账本成本口径，不宣称替代券商逐税务批次申报。

比例精度使用整数比，数量／金额使用明确的十进制定点或有理数边界转换；不得用反复浮点乘除推导一连串拆股。容差按输入精度制定；不能为通过对账扩大容差。

## 5. 回放、成本与排序

### 5.1 股票和期权的转换

1. 重放到行动生效前，定位该账户和标的的持仓、股票成本、期权余额及尚未实现的权利金。
2. 对股票应用明确数量腿，保持股票和税务口径总成本；现金替代处置另行计算。零股、空头、碎股均测试。
3. 对每个未平旧期权，按证明转移剩余张数和 `openPremium/openShortPremium`；保留过去已经实现的收益及其日期。
4. 转换不得调用普通平仓分摊函数，把旧合约归零误当成“全部权利金已实现”。新增专用转换函数。
5. 同一目的系列收到多个余额时合并金额与数量并保留来源明细；经济方向发生抵消不能凭净额隐瞒，需确认是否确属同一系列和合法转移。
6. 行动之后的平仓、C/O 反向开仓、指派、行权、到期按新条款执行；成交自身只保存券商当时的单位和现金。
7. 连续拆股顺序应用；历史报表、近 30/90/365 天收益和按到期日的卖方权利金分组不得被迁移到行动日。

标准 2:1 手算金标准（价格与数量为合成数据）：

| 步骤 | 预期 |
| --- | --- |
| 买 100 股，每股 80；另卖 2 张 Put，K=100、每张乘数 100、权利金报价 4，无费用 | 股票成本 8,000；空头 2 张，未实现权利金 800 |
| 2:1 转换 | 股票 200 股、每股成本 40；空头 4 张 K=50；未实现权利金仍 800，已实现收益不变 |
| 回补新合约 1 张，报价 1，费用 1 | 现金 -101；释放开仓权利金 200，实现期权净收益 99；余 3 张、未实现权利金 600 |
| 再指派其中 1 张 | 股票增加 100、交割现金 -5,000；剩余 2 张权利金 400；该次分摊权利金 200 按既有税务口径进入交割成本 |

该算例之外必须测试带舍入的行权价，不能要求所有公告系列都满足未舍入的行权本金恒等式；任何差异必须由明确条款解释。

### 5.2 时间线必须跨合约验证

当前后端的单合约 SQL 过滤不足以验证转换链。引入账本级／账户级的完整受影响时间线验证，包含转出、转入以及其后的所有依赖事件；冲销、追加、批量、重建、恢复共用。首版优先完整回放正确性，再在等价测试下优化。

新增排序依据同时落实到 JavaScript、Python、导入预览和导出：

- 保存券商原始 Date/Time 和 Report Date；经济生效点单独保存。
- 官方明确盘前生效的行动先于该生效日的拆股后交易；同日旧单位记录需有明确归属依据，不能仅按到达顺序判断。
- 有可靠精确时点用精确时点；只有日期时保存“盘前生效”等已证明阶段，不伪造 `00:00:00` 原始成交时间。
- 同日早行权、盘前／盘后成交、公司行动延迟记账必须按实际条款生效边界分类。无法判断先后时进入缺项流程。
- 没有公司行动影响的旧事件保留原 `trade_date → broker_timestamp → seq` 语义；同一行动的内部腿原子执行。

## 6. CSV / Flex 的完整导入链

### 6.1 识别、分组与证据

替换“一遇 Corporate Actions 就报错”为以下流程：

1. 读取 Activity 中英文段和实际 Flex 公司行动布局，正确绑定每组表头；先按账户、标的身份、资产类型和币种过滤，再识别公司行动类型。不能用任意字符串包含 TQQQ 代替身份核对。
2. 原行保留数量、金额、报告日、生效日和引用。区分汇总／明细、原证券减少／新证券增加、股票／期权系列调整，不重复计算父子行。
3. 优先用明确事务关联与条款配对旧、新腿；缺少公共引用时，仅在行动身份、日期、数量及完整条款唯一匹配时自动分组。数量列可能是增量或出入库腿，不默认它就是比例。
4. 标准比例、确切系列表或已核实规则生成候选。发行人日期证明股票行动；期权调整需要对应的系列条款证据，不能仅凭股票公告推定全部期权。
5. 有冲突或缺项时显示具体原行、缺失字段和“补充拆股资料”入口；用户补充的映射保存为有来源的规则，经完整回放核对后才能提交。
6. 本标的其他未知公司行动保留阻断；其他账户／标的公司行动不干扰本账本。无公司行动段与“已检查且本期没有行动”是不同状态。

规则资料可存为本地版本化记录，包含公告链接、核实日期、适用系列和修订摘要。初始规则 fixture 可以覆盖已核实的 TQQQ 样例；不能要求每次联网才能重放已入账历史，也不能下载新公告后自动改变历史结果。未来行动通过同一个资料入口补齐，不靠新增硬编码日期。

### 6.2 先转换，再推导期初

期初推导必须使用整段行动时间线。跨一个 2:1 拆股，最简单的股票关系是 `期末 = 2 × 拆股前余额 + 拆股后净变动`；存在多个行动和交易时按各边界分段求解，不能用“期末减全期成交数量”。

- 期权期初在旧、新系列之间按明确转换关系反推，并与可用的历史余额及 Basis 证据核对。
- 缺少映射、不可逆的现金替代或不明确的余额不能倒推成零成本开仓；列出具体未解释残差。
- 仅导入拆股后的报表时，已证明的期初属于拆股后单位；不能再应用报表区间外的历史行动。
- 先有拆股后期初存根，再补跨拆股历史时，比较的是转换后的同一经济余额和可归属成本；证明完整后同事务替换存根。
- 无持仓、无交易但存在公司行动资料的月份仍需正确检查；不得因草稿数为 0 跳过核验。

### 6.3 去重、修订与重叠

- 同一行动被月报、年报、Activity、Flex 重复描述，只应用一次。文件摘要用于绑定预览，不作为行动唯一性证明。
- 先手工登记旧 `split`、后导入报表：显示“已有股票调整，需补全／核对期权”。若完全等价，建立来源关联；若需完整替代，原行作废、新复合事件替代，并在同一事务验证，股票比例不能应用两次。
- 相同事务引用但比例、时点、目的条款或金额变化是修订冲突；不能当作第二次拆股。没有共同引用的疑似重复也不静默跳过或自动相加。
- 跨行动的 TWS 原始成交按其当时身份和单位匹配月报；只有已证明的报表单位转换规则才允许比较经济等价，不改写券商引用。
- 保留 Order＋Trade 子行＋部分 TWS 已入账＋C/O 的联合路径；剩余分笔在完整时间线中重标纯平、穿零、纯开，不能复制父行标签。
- 普通追加、整本重建采用同一解析和回放结果；重建只与重建文件及显式补充证据比较，不因旧账本已有引用漏掉新历史。

## 7. TWS 对账与用户操作

### 7.1 预览与补齐入口

CSV 预览增加“拆股与合约调整”分组，逐行动显示：

- 生效日期与比例、证据来源；股票数量／总成本／每股成本前后对照。
- 旧期权 → 新期权、张数、行权价、报价乘数、交割包、承接权利金。
- 已有调整、拟新增、需补齐、冲突及现金替代待结算的状态。
- 缺项的精确原因和可填写／选择的新旧条款；修改资料会使旧预览失效并重新核验。

证据齐全时用户确认整批入账。缺项草稿可保存并恢复，但与活动账本分开，不计持仓、现金或报表覆盖；文件／条款／账本版本改变后重新计算。

### 7.2 TWS 单笔、普通拉取和批量归账

1. 对账始终以已确认行动回放后的当前持仓对比完整 TWS 快照，不能自动“采信”数量差额。
2. 同时出现股票翻倍和旧期权消失／新期权出现，可以提示“疑似缺少拆股记录”；不能单靠这个图案认定行动或自动写事件。
3. 批量“查找 TWS 成交”保留该类差异为“公司行动待核对”，给出报表／条款入口；不能生成虚假买卖来消差额。
4. 调整已确认后，普通拉取和批量归账才能用新合约去匹配后续成交。旧、新合约引用冲突不能以结构相似或数量相等强行匹配。
5. 预览有效性绑定账本版本、行动资料版本、合约条款及实际持仓指纹。仅快照广播时间改变不使预览过期；断线、账户切换、数量或条款改变会失效。
6. 股票、期权、期货净数量为零的往返成交，以及缺佣金行继续可见；不能在新增行动分组时重新丢掉它们。

保留现有一次确认、原子批量写入的交互。只读合约资料查询可复用现有 IB 适配器；不增加下单通道、持续行情订阅或自动记账。

## 8. 交割、What If 与压力测试

所有消费者使用同一份当前有效条款。标准 TQQQ 转换完成后，What If、卖方权利金面板和压力测试应正常工作；图表和异步 worker 缓存必须包含条款版本。

一般的单标的交割包，设每张包含 `d` 股、现金 `c`，行权本金 `X`，则到期 Call 内在价值为 `max(d × S + c − X, 0)`，Put 为 `max(X − d × S − c, 0)`。按实际多空和履约方向记录股票与现金；不能继续用“报价乘数＝交割股数”的公式。真实履约仍以券商事件为证，不由情景预测自动入账。

- 权利金交易现金使用报价乘数；现金交割使用行权本金和交割包。两者分别校验。
- 一股标的＋确定现金的到期计算纳入本轮，要求四种多空 Call/Put 金标准及现金／股数守恒。
- 到期前的非标准期权估值需要明确受支持模型；没有验证的模型时保留持仓与已知现金，显示不能估值，不能套标准 BSM／CRR 或把缺失腿按 0 计。
- 标准合约下，在相同经济时点以 `S/r`、新数量和新条款估值，无舍入调整的算例应保持组合价值；真实公告舍入单独按实际条款计算。
- 尚未核实的历史拆股不能导致所有无关导入被拒绝，但相关未平期权、依赖交割的 What If 和完整组合估值不得显示已核实结果。
- 已过拆股的报价基准必须与当前持仓单位一致；旧报价缓存不得混用。本轮不预测尚未发生且条款未知的未来拆股。

## 9. 事务、迁移、备份与兼容

1. 使用实施时下一个未占用 schema 版本；当前基线为 v9。扩展 CHECK 必须在迁移事务中重建所需表并重建索引，故障不能留下半迁移状态。
2. 不改写历史交易；旧 `split` 原样读取。旧未解决期权提示仍可见，修复入口以显式替代计划处理；混合账户旧账本不得自动分配行动。
3. 新事件／条款／来源别名／待结算权益全部纳入账本摘要。修改任何一项都让基于旧版本的预览失效，不能只哈希旧字段。
4. 继续复用 `import_cost_basis_events`／重建／恢复的原子事务；增加的行动补齐或替代操作也要求完整 bookIdentity、expectedLedgerVersion 及固定幂等 token。后端在写锁内重验完整依赖链。
5. 单独冲销有后续依赖的行动必须拒绝，并指出受影响事件；允许明确的“替代行动＋必要修复”同事务提交。已作废来源不得通过重复导入复活。
6. 源引用关联、行动条款和待结算权益随整本重建／清空一起存档，随存档恢复完整恢复；整本永久删除清理对应子表。覆盖记录增加公司行动检查状态；回补历史或修订行动使生效日起依赖证明失效。
7. JSON 备份升级为能保存新增数据的版本；支持导入旧 v1 的兼容分支，不能把旧 split 升格为已核实映射。新备份缺字段、截断、摘要不符或未知版本均拒绝。
8. 审计 CSV 导出明确公司行动组与各腿，不伪装成成交；新增字段纳入导出、恢复、分页及摘要测试。未知事件类型的旧客户端必须刷新，不能显示漏算后的账本。
9. Live／Historical 后端挂载同一协议与存储模块；CSV、手工补齐、离线回放不依赖 TWS。涉及真实合约资料查询的能力在离线时明确不可用。
10. 增加 payload 上限检查但不随意扩大全局 WebSocket 上限；超限在预览阶段提示，不能拆成多次可见的半账本提交。

数据迁移只在临时库与复制样本上验收；实施及自动测试不擅自修改用户真实账本或重启券商连接。回退应用版本前必须处理数据库／备份版本兼容，不能让旧代码静默忽略新事件。

缺项恢复要有反向验收：相同输入补齐所要求的那份证据后，必须能够成功导入；“始终拒绝”不能作为修复通过。

### 11.2 随机状态机与变形测试

扩展现有 Python Fraction 独立模型，不调用生产转换函数来生成预期。生成器先产生经济历史与明确系列规则，再独立编码成报表、TWS 成交和快照。必须生成公司行动段和真实页面提交结构，不能只把 `split` 对象送入核心。

强制组合覆盖：0–3 次行动、四类多空期权、分笔、部分重叠、C/O、同日边界、历史回补、期初替换、碎股款分期到达、身份冲突、重复与修订、旧告警及失败重试。至少一个专用生成器每个案例都同时包含 I06 的五项条件；不能依赖随机碰巧覆盖。

变形不变式：

- 无舍入、无现金替代的拆股，再做逆转换，回到原数量、成本及未实现权利金。
- 同一经济历史分别整本导入、合法分批追加、TWS 后补月报、重建、备份恢复，规范化后的经济结果一致。
- 只重排具有明确时间依据的输入，结果不变；没有可证明顺序的同秒记录不得擅自重排。
- 修改账户、币种、条款或丢掉一腿，必须被拒绝；补回后成功。坏批次前后的完整数据库摘要相同。
- 拆股时保持总额，按正确比例缩放每股／每张金额；既有实现收益不会被重新计入另一个时间窗口。

拟定执行门槛：日常 CI 300 个固定种子，其中至少 60 个穿过临时 SQLite；合并前 10,000 个种子、每个至少 80 个主要动作，其中至少 1,000 个走完整数据库状态机，并补一组此前未用的新种子。报告按各矩阵项列出命中数；次数达标但有必测格未命中仍失败。

随机失败输出种子、规则版本、报表、TWS 重叠位置、预览请求及重跑命令。缩减时保留引发失败的转换链和经济合法性，每个修复变成永久固定反例。任何跳过／样本缺失分别报告，不计通过。

### 11.3 真实资料与测试隔离

- 从官方公告提取必要的规则事实形成精简 fixture，合成账户与成交金额；不把用户完整账单上传 GitHub。
- 必须增加真实跨拆股的 Activity 与 Flex 样本（脱敏或本机显式配置），包含拆前开仓与拆后结算。只有公告，没有实际报表，不能宣称已验证券商导出格式。
- 之前提供的 2026 年报表即使回归通过，也不能据此宣称覆盖了 2025-11-20 的生效边界；先确认样本实际包含哪个行动。
- 尚无真实格式样本时继续做合成及隔离集成测试，并在验收报告留下未完成项；不能把它改成通过。
- 全部自动写入使用临时 SQLite；浏览器拦截网络或连接临时后端；真实 TWS 仅在明确的只读核验范围内使用，绝不发送交易订单。

- 预览和后端提交认可同一组合法数据；后端也拒绝绕过预览的错误数据。
- 已有 C/O、TWS 重叠、批量往返、缺佣金和“只拦新增回放错误”回归继续通过。
- 文档分别写清支持的行动、需要的报表字段、缺项补齐步骤、非标准估值限制和旧账本修复方式。
- 执行 `node tests/run.js`、账本 Python 全套、新增专项／随机测试及隔离浏览器测试；新套件纳入正式入口，真实格式缺失不能混在绿色总数中。
- 发布前记录实际修改范围、数据库及备份版本、测试结果、剩余限制和回退方案。完成计划不等于完成实现；完成随机次数也不等于证明所有输入正确。
