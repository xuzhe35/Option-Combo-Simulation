## 1. 现状（改动锚点）

## 2. 三条路径的定义

`start` 是冻结的本账本快照标的价；`end` 是当前扫描点的终点价，扫描中心可以与 `start` 不同。
当 `target > asOf`，统一用归一化时间 `u = clamp((t − asOf) / (target − asOf), 0, 1)`
和终值变动 `Δ = end − start`：

| 键 | 名称 | 路径价 `S(u)` | 参数 |
| --- | --- | --- | --- |
| `immediate` | 立即到位并保持 | `end` | 无 |
| `gradual` | 逐日线性到位 | `start + Δ·u` | 无 |
| `overshoot` | 先过冲再回归 | `u ≤ τ`：`start + mΔ·u/τ`；`u > τ`：`start + mΔ + (1−m)Δ·(u−τ)/(1−τ)` | 转折时点 `τ`（默认 0.5，范围 0.05–0.95）；过冲倍数 `m`（默认 1.5，范围 1–3） |

要点：

- `overshoot` 在 `m = 1` 时为**在 τ 时刻提前到位，然后保持**，`τ` 仍然有效；不等于 `gradual`。
  不对 `m = 1` 单独切换为线性，保证 `m → 1+` 时路径价格连续。例：`100 → 80、τ = 0.5`，
  `u = 0.25` 时 `m = 1` 得 90，gradual 得 95；`u = 0.5` 以后前者保持 80。
- 形状对上下两侧对称：终值下跌时是「先跌到 m 倍再反弹」，终值上涨时是「先涨过头再回落」。
  控件文案只描述下跌侧（用户关心的是保护），说明里注明上涨侧对称。不为上涨侧另做一条线性路径，
  否则同一条曲线在零点两侧用两种规则。
- `Δ = 0` 时，本账本路径恒为 `start`。本方案不能表达「先大跌、最后完全回到起点」，
  也不能在终点上涨时表达先跌后涨；这属于终点变动倍数参数化的范围限制。
- **价格域**：冻结起点必须有限且大于 0；沿途本账本价格允许恰好为 0，不允许负值或非有限值。
  对每个扫描终值，分段路径最小值为 `min(start, end, start + mΔ)`；负值 →
  `invalid_stress_path_shape`，整条曲线不可用，提示缩小扫描范围或倍数。不得使用 `m·|Δ|/start`
  判定上涨侧，也不把零价称为负价。该校验必须覆盖完整扫描区间，不依赖是否有合约在谷底到期。
  联动映射还需满足自身定义域；例如反向复利映射遇到零总收益无法给出有限价格，应报映射错误，不补零。
- 当扫描中心等于起点时，扫描 ±50%、`m = 1.5` 的最低点为起点的 25%，合法；
  中心偏移时必须使用实际 `start` 与扫描边界重新检查。
- `target === asOf` 时三条路径都退化为终值，不计算 `u` 的零分母、不检查未实际经过的谷底；
  路径键及显式参数自身的合法性仍需校验。有效参数下输出估值相同，序列路径元数据可不同。

## 3. 内核改动

1. **路径对象**。`opts.path` 继续接受字符串；新增 `opts.pathShape = { trough: τ, overshoot: m }`，
   只在 `path === 'overshoot'` 时读取并校验；缺省用默认值。编译结果 `compiled.path`、`compiled.pathShape`，
   序列输出 `series.path`、`series.pathShape`。非法形状 → `invalid_stress_path_shape`；非法键 → 现有 `invalid_stress_path`。
   `trough` 保留为字段名，UI 称「转折时点」。缺失字段使用默认值；显式空白、非数值、非有限或越界输入报错，
   不在正常估值入口静默纠正。非 overshoot 路径忽略形状参数，输出 `pathShape: null`。
2. **`pathSpot` 改为查表**：`PATH_SHAPES[path](start, end, u, shape)`，三个纯函数放到
   `js/cost_basis_stress_models.js`（`pathSpotImmediate/Gradual/Overshoot`），可单测。
   端点 `u = 1` 明确返回 `end`，避免不同公式的浮点运算顺序影响终点兼容性；全扫描域校验在估值循环前执行。
3. **冻结起点**。新增运行时输入 `opts.pathAnchor = { price, asOfInstant }`，从本批次快照及已解析的
   情景起算时刻生成；编译结果和序列均带出解析后的 `pathAnchor`。未显式传入时，可从有效当前快照推导。
   - `price` 必须有限且大于 0，`asOfInstant` 必须是有效带时区时刻并与本次编译的 `asOf` 一致；
     完整快照仍在时还要核对价格一致，并保留现有快照同步性门禁。冲突 → `invalid_stress_path_anchor`。
   - 页面在创建原始 `seriesOptions` 时冻结该对象与 `asOfInstant`，所有降级分支原样保留；
     不能在清除快照后重取当前时间或扫描中心，也不能从别的账本、旧刷新批次借用起点。
   - 正时长的 gradual / overshoot 必须有起点，缺失 → `missing_stress_path_anchor`；
     联动价格映射同样必须有本账本起点，immediate 也不例外。
   - 无联动的 immediate 或零时长静态结算可继续使用原有无快照降级，不虚构 `pathAnchor`；
     它不恢复「较快照变化」比较项，也不放宽存续期权所需报价门禁。
   - 起点是本次计算输入，不是每账本偏好，不写入 `kernel` 记忆。`centerPrice` 只控制扫描范围。
4. **联动路径价按时刻映射**。提取共用的按时刻取价逻辑，供终点估值与途中结算调用：
   - 本账本路径价为 `S_own(t)`，传入映射 API 的百分数为
     `changePct(t) = 100 × (S_own(t) / pathAnchor.price − 1)`，单位是百分数点，不是小数收益率。
   - `elapsedYears = (t − asOf) / YEAR`。启用暴跌放大时，
     `sigmaScale(t) = M.crashSigmaScale(changePct(t) / ratio)`，否则为 1。
     明确沿用现有简单收益代理；不改为映射后的联动跌幅，不引入 σ 与映射价格的循环求解。
   - 调 `M.mapLinkedUnderlyingPrice(basePrice, changePct(t), ratio,
     { mapping, sigma: compiled.sigma === null ? null : compiled.sigma * sigmaScale(t), timeYears: elapsedYears })`。
     该 σ 是截至取价时刻的映射假设，不模拟历史方差积分或谷底记忆。
   - `t = target` 时本账本直接取 `end`，沿用现有终点映射的输入和计算顺序，保证 `mapped`、
     终点 IV 冲击以及存续腿估值不变。`valuePosition` 的存续分支仍使用对应标的终点价与当前价做定价及 OTM 判断，
     不得因调整到期分支而把本账本价格误传给联动存续腿。
   - 线性映射保持现有 `max(0, basePrice × (1 + changePct(t) / 100 / ratio))`；
     在未触及零价截断的范围，gradual 与旧线性插值相同。触及截断时应按时刻映射，不能要求旧结果一致。
   - 保留现有 `elapsedYears ≤ 1/365` 的单日简单收益规则；超过一天使用多日复利近似。
     这一分段切换可能造成联动映射不连续，本次不平滑或改写它，需补边界测试并在假设说明中披露。
   - `immediate` 表示**本账本**立即到位并保持。复利联动价仍可随 elapsedYears 变化；
     不承诺各到期日都按联动终点价结算。正常 immediate、gradual 的途中联动结果都可能改变。
5. **明细字段**。`valuePosition` 对已结算腿返回 `settledAt`（到期时刻 ISO）、`settlementSpot`（该腿标的路径价）、
   `settlementPathU`（归一化时刻，零时长统一为 1）及 `settlementType`（`physical` / `cash`）；
   保留 `delivered` 和有符号 `settlementCash`。对未结算腿不加这些结算专用字段。
   `sweep` 原样带出，并在每个 `details[]` 项附上 `symbol`、`account`、`right`、`strike`、`expiry`、
   有符号 `contracts`、`multiplier`、可用的 `conId` / `localSymbol` 及原有 `identity`、`linked`。
   展示按不同合约逐行，张数单列；不把 10 张相同合约展开为 10 行。
6. **不改**：交割股票持有到终点按终值估值；联动到期变现现金持平；`scenarioCost` 缓存键仍是 ITM 位图
   （位图变了自然重放）；区间成员共用路径；每周假设收入按天数不变。
   Long Put 实物行权卖出股票并收取执行价本金，Short Put 指派买入股票并支付本金；
   本账本交割净值为 `delivered × (end − strike)`，不能改成到期时的内在价值现金。

1. `#stress-path` 增加第三项「先跌到更深再反弹（过冲后回归）」。选中时显示两个半宽输入：
   「转折时点（占天数比例）」`#stress-path-trough`（0.05–0.95，默认 0.5）和「过冲倍数」`#stress-path-overshoot`
   （1–3，默认 1.5），带 title 说明：`1` 表示在转折时点提前到位并保持；
   `1.5` 表示终值跌 20% 时途中最深跌 30%；上涨侧为先涨过头再回落。
   两个输入放在「情景」组，紧跟「到位路径」之后，按现有 `.half` 规则并排。
2. 状态 `state.stressPathShape = { trough, overshoot }`；每账本记忆 `kernel.pathShape`；恢复时非法值回默认。
   输入事件走现有的 `_writeStressLinkedMemory(); _renderStressTest();`，不触发行情刷新（路径不影响快照）。
3. 状态行路径文案三选一：「本账本立即冲击并保持 / 线性渐变路径 / 过冲 1.5× 于 50% 时点后回归」。
   `m = 1` 显示「于 50% 时点提前到位并保持」；零时长显示「同一时刻冲击」；
   起点缺失、冲突或路径非法时显示对应原因并清空图、tooltip 和切片，不显示旧结果。
4. tooltip：在现有结算结果之后，按本账本 / 联动标的分别汇总**实际已结算腿**的
   `settlementSpot` 最小值和最大值，附标的名称与币种，例如「TQQQ 已结算价 USD 61.20 ～ 68.40」。
   取所有结算腿的 min/max，不能仅取时间最早和最晚两项；不同标的不得合并成一个价格区间。
   单一价格只显示一个数；无结算腿不显示；范围包含恰在终点结算的腿，不声称是整段路径的极值。
   immediate 下本账本可省略重复价格行，联动已结算价仍显示。不逐张列。
5. 切片核对新增第四栏「到期结算明细」：逐合约列出可读身份、张数、`settledAt`、`settlementSpot`、
   结果及交割股数、有符号现金。按结算时刻及稳定合约身份排序，并按本账本与联动分组。
   本账本结果为指派 / 行权 / 归零，联动为到期现金变现 / 归零；不把联动变现标成实物行权。
   时间采用明确标注的纽约时区，现金标明收到 / 支付，零值明确显示。
   immediate 下仍列明细，可补「本账本按终值结算；联动按各到期时刻映射价变现」，
   不用「全部按终值结算」替代实际数据。无结算腿显示空状态。
6. 「分项口径与假设说明」加一句：路径决定途中到期合约的结算价与交割；IV 冲击仍按终点跌幅计算，
   不模拟谷底 IV 的记忆效应；交割股票持有到终点按终值估值。
   另注明：零终点变动不包含先跌后完全修复的路径；联动采用单日 / 多日分段映射，跨一天边界可能不连续；
   此视图展示终点结果与到期结算，不展示最大途中亏损、峰值资金需求或保证金。

## 5. 与区间、降级、Worker 的关系

- 区间成员共用 `compiled`；`path`、`pathShape`、`pathAnchor`、`asOfInstant` 均进入 `_stressSeries`
  的缓存键（在 `options` 里）。改路径、参数或刷新起点即取消旧任务，重算中线与区间，拒收旧 generation。
- 降级曲线（联动缺失 / 仅到期结算）沿用同一路径参数、冻结起点和起算时刻；清除不可用期权报价时
  不清除已冻结起点。若最初就没有有效起点，正时长 gradual / overshoot 停止，不能回退到扫描中心或 immediate。
  新的路径 / 起点错误不加入行情缺失降级白名单；较快照变化仍遵守原有完整基线门禁。
- Worker 消息结构不变：`options` 整体传入，`pathShape` 和 `pathAnchor` 随之透传并出现在返回的 `center` 序列上。
  增加 Worker 与同步内核的结算明细、中线、区间一致性断言，不能只检查参数字段存在。

## 6. 测试

内核 `tests/cost_basis_stress.test.js`：

合成算例显式设置冻结起点、起算时刻、终点时刻、合约截止时刻、扫描点和数量；
“第 5 天 / 第 10 天”分别为精确的 `asOf + 5×DAY / 10×DAY`，不依赖日历日期默认收盘时间。
对结算使用独立现金与持仓恒等式作 oracle；不能只调用生产映射函数再拿返回值当预期。

1. **形状纯函数**：三个 `pathSpot*` 在 `u = 0 / τ / 1` 的值，转折处左右连续，上涨 / 下跌对称。
   `100 → 80、τ = 0.5、m = 1` 在 `u = 0.25 / 0.5 / 1` 得 `90 / 80 / 80`；
   gradual 同时刻得 `95 / 90 / 80`；检查 `m → 1+` 收敛到提前到位路径。
   `Δ = 0` 恒价，immediate 忽略 `u`。`τ`、`m` 缺失用默认，显式空白、非数值、非有限、越界报错。
2. **保留现有跨期回归**：起点 100、终点 80、K85 Long Put 第 5 天到期，终点第 10 天；
   gradual 到期价 90、归零；immediate 到期价 80、实物行权。不要把 centerPrice 当成 start。
3. **谷底结算与现金方向**：起点 80、终点 70、第 5 天 K85 Put 到期，终点第 10 天，
   `m = 1.5、τ = 0.5`，到期价 65。无初始股票，每合约 100 股，开仓权利金每股 5、无费用，分别测试：

   | 持仓 | 结果 | 交割股数 | 收到本金 | 支付本金 | 终点交割净值 | 含开仓权利金的本账本盈亏 |
   | --- | --- | ---: | ---: | ---: | ---: | ---: |
   | Long Put 1 张 | 行权 | −100 | 8,500 | 0 | 1,500 | 1,000 |
   | Short Put 1 张 | 指派 | +100 | 0 | 8,500 | −1,500 | −1,000 |

   两者 `details.settlementSpot = 65`；现金符号与股数分别核对。每股成本单独用账本引擎验证，
   不把本表的权利金或内在价值重复记入交割本金。补 Call 多空、恰好平值归零和多到期日排序回归。
4. **先跌后反弹，区分两种交割策略**：起点 100、终点 95、K92 Long Put 第 5 天到期，
   终点第 10 天，`m = 2、τ = 0.5`，到期价 90；immediate 则为 95、归零。
   本账本无初始股票时交割 −100 股、收到 9,200，终点交割净值 `9,200 − 100×95 = −300`，

## 8. 不做什么，以及为什么

- **IV 记忆**：本方案仍按终点跌幅计算 IV 冲击，不模拟反弹后的波动率残留。
  若真实 IV 高于该假设，多头保护价值和空头期权负债都可能被低估；对组合盈亏的影响取决于持仓，
  不能统一称为「偏保守」。引入记忆需要新的历史研究与验证，不在本次范围。
- **资金利息与分红现金流**：路径上的交割现金和股票持有到终点不计利息、不计分红，与现状一致。
- **提前指派**：美式树给出行权权利价值，路径不模拟提前指派时点。
- **独立谷底幅度与完整反弹路径**：过冲幅度绑定 `Δ`；`Δ = 0` 时不能表达先跌后完全修复，
  终点上涨时不能表达先跌后涨。未来若需要这些情景，再增加独立转折价格 / 幅度，不在本次暗中改变公式。
- **途中最大亏损、资金与保证金**：此视图计算终点价值和到期结算记录，不模拟逐时刻账户风险，
  不能用终点盈利证明途中资金充足。
- **随机路径 / 蒙特卡洛**：本次仅增加三条确定性情景；随机模拟不在本次范围。
- **上涨侧单独形状**：见 §2，对称处理。
