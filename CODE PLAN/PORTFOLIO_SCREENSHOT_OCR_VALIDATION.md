## 2. P0 冻结内容

- `tests/fixtures/portfolio_snapshot/contract_v1.json`：20 个可编辑字段、数字为十进制字符串/null、
  账号手填、持仓日期初始未知、仅可见范围、源行和原子持仓分离、确认不消除缺项。
- DOM-free schema/core：严格数字/百分比/日期解析、父子去重、缺项提示、人工修改记录、
  JSON 的脱离引用检查与导入结构校验。分组/组合父行不能作为 position 引入。
- 私有原图的逐行目读基准：15 条原子持仓、1 条现金、6 条分组、1 条组合父行，共 23 行。
  每条原子持仓比较 16 项，包含数量、方向、类型、合约字段及主要金额。
- 到期分组不是持仓日期；图片通知不是账号来源。三条截断 CA/CAL 的 right 保持未知。
- 基准来自逐行目读，不由生产解析器反推；尚未声称用户已经复核或独立人工签署。

私有目录 `tests/private_portfolio_snapshot/` 及原图目录 `Portfolio SC/` 均已忽略。
公开 Git 中只有合成 ABC/2030 年用例及不含真实持仓的契约。

## 3. P1 页面能力

入口：`cost_basis.html` 的「截图 Portfolio」新 Tab，或直接打开 `portfolio_snapshot.html`。

- 点选和整页拖拽单张 PNG/JPEG，校验实际签名、4 MiB、8192 边长及 2000 万像素。
- 原图缩放、选中行定位/高亮、独立横向放大行；点击字段自动滚动到对应原图列。
- 原子持仓表，可切换关键字段/全部识别列；筛选待核对、疑点、已修改。
- 20 个逐字段编辑入口，保留原 OCR 字符串；修改实时进入唯一内存 JSON。
- 逐行人工确认；修改会让行重新待核对，未知字段即使确认也保留缺项。
- 现金独立编辑与确认，分组/组合父行单独显示，不混入持仓数量。
- 账号/持仓日期手填；日期精度为 date，不编造时刻或使用文件名/上传时间。
- JSON 查看、复制、导出、导入；`window.__portfolioSnapshot.getSnapshot()` 返回深拷贝。
- 同图重附不覆盖校对；换图清空前提示；重新识别须对比后明确采用新结果。
- 识别超时/取消/换图/导入会废弃旧任务，迟到结果不得覆盖当前表。
- 无效输入阻止确认/导出，无法读取的字段保持 null，不自动猜字符或补零。

注意：JSON 不包含原图文件，原图仍需用户自己保留。刷新前导出；无浏览器永久草稿或正式存储。

## 4. 实际识别方案与计划调整

本阶段用 `scripts/portfolio_snapshot_ocr_server.py` 独立 HTTP 服务（127.0.0.1:8798），
调用 `scripts/portfolio_snapshot_vision.swift` 的 Apple Vision accurate 识别。
服务只允许 loopback 的 Host/Origin/peer、静态 allowlist 和有限大小的图像请求。
图片临时落入私有临时目录，识别后删除；本地编译产物只缓存到此服务结束。
不调用云模型、不需要 API key，不读取业务库，不建立 broker 会话。

用户要求首阶段即可实际看见识别信息，因此提前实施了 P2 的单图通路。
为隔离原有交易服务，当前没有实现计划 §8 的 WS 动作目录；后续挂载必须另做对应协议验收。
当前 OCR 仅支持 macOS + 已安装的命令行工具。其他平台仍可使用内存表格/JSON，未提供 OCR 适配。

数字词法层处理了两种实际观察到的格式：负号后空格、末尾状态圆点；不改变数字字符，原文完整保留。
LAST 价格的 c/M 等券商前缀保持未确认，不静默删掉。

## 8. v2 重读与通用组合结构复核（2026-10-20）

### 8.1 改了什么与采用条件

首次整图文字不改动。Vision 针对包含短代码的文本区域裁剪、放大 2× 与 3×，各重新识别一次。
前端只处理描述列中的短代码，并同时要求：同一源文本行、原图定位框有足够重叠、两种不同尺度、
两个候选完全一致且括号结构一致。匹配不唯一、错位、只有一次或结果分歧均保留首次值。
不改变数量、日期、金额，不把带省略号的 CA/CAL 补成 CALL。

当前两处首次值 NO 在两种尺度都读取为 NQ，所以结构字段采用 NQ；
`fieldEvidence.originalValue` 仍为 NO，`recognizedValue` 为 NQ，`corrections` 保留两次坐标和文本。
UI 字段旁显示首次/重读对照，所有行仍待人工核对。合成测试中，两次均读取为 NO 的代码保持 NO，
其他字母组合可按相同证据规则改进，不存在 NQ 专用分支或替换表。

### 8.2 组合一般化的范围与边界

原版只识别少数策略提示，且会一直沿用父组合到下一个 TOTAL，不能据此宣称通用。
v2 改为：

1. 以实际文字横坐标建立缩进栈，区分父/子/同级，遇同级新行即退出上一组合。
2. 结合描述能否构成单一股票、期货、OPT/FOP 合约；未知名称有缩进子行时可识别为汇总。
3. 策略词只辅助识别折叠行；类似策略词的单独 ticker 或 trading class 不触发组合分类。
4. 嵌套父行均不进入 positions，每个可见原子腿只出现一次，保留其实际多空数量，不假设比率。
5. 父行记录可见 childRowIds / atomicLegRowIds。expectedLegCount 恒为 null，不猜测配方或总腿数。
6. 没有可见子腿、只有一条腿、角色不明确时显示结构疑点，不把父行作为额外仓位、不生成虚拟腿。
7. 对形似单独股票但又有缩进子行的歧义行暂不自动定角色，列为未分类，并提示范围不完整。

UI 可查看组合原图和逐腿跳转。`expanded_visible` 只表示已展开的可见腿，**不证明所有腿已被截图覆盖**。
一般化针对当前支持的 TWS 列布局和可见层级，不保证能猜出无缩进、无策略信息的任意陌生版式。

## 10. 类型前缀与批量确认（按用户后续要求调整）

用户确认可按 CA / PU 前缀判断期权类型，并希望目视扫图后批量确认，不要求每行点击。
因此覆盖此前“截断 CA/CAL 保留未知”及逐行确认的操作约定：

- 到期日、行权价之后的独立类型词 CA / CAL / CALL 与 PU / PUT，可带 `...` 或 `…`，
  分别识别为 C / P。不会把 CASH、CALENDAR、PUTNAM 或仅 C / P 字母按此前缀解释。
  原文不补写成完整 CALL/PUT，字段保留 `option_right_prefix` 解释，并在核验区展示。
- 「批量确认全部」一次确认全部原子持仓及现金，包含筛选隐藏行；不需要再次逐行点击。
  不会把组合父行计入持仓，不清除缺项或结构疑点，不声明截图覆盖完整账户。
- 后续编辑只撤销受影响行的确认。现金修改、勾选确认也同步整体核验状态。
  无效输入期间不能批量确认；识别处理中不能批量确认；空表不能确认。
- 原图三条截断 Call 的私有目视基准更新为 C；其他字段基准保持不变。

阶段套件新增前缀边界、批量确认保留原始证据及修改失效检查，共 24 项。

## 11. 第二张真实截图：单字符期货数量漏读

用户新图中一条期货行的 POS 是单字符数量；首轮 Vision 根本没有输出该单字符，
因此 `rawCells.quantity` 缺失，前端得到 null，而合约、日期、价格已正确识别。
不是 FUT 被排除，也不是表格丢失服务端已有的数量。原图汇总行中的 1 同样未形成首轮词框。

增加通用空数量单元格重读：从 FIN / MARK / POS 表头定位当前支持的列布局，
按各描述行定位空 POS 单元格，最多 64 个有界裁剪。普通描述重读仍为 2× / 3×；
数量改用 3× / 4×（本图 2× 仍漏读，3×、4× 都读到 1）。
前端仅在首轮数量真正为空时接受：一个匹配当前行和 POS 列的裁剪、两个不同尺度、
两个完整合法数字一致。已有数字、无法解析的已有文字、分歧、单尺度、邻行/汇总、

## 20. 可切换的 RapidOCR 引擎与逐格复核（2026-10-21）

### 20.1 为什么是逐格复核

先在已知单元格边界上实验：RapidOCR 只做识别、紧贴裁切时，三张原图 517 / 517 个数值格、47 / 47 条

- `scripts/portfolio_snapshot_rapidocr.py`（新文件，`pip install rapidocr`，模型随包、运行时不联网）：

### 22.5 规则调整：首读与同格复读不一致时保持未知（2026-10-21，用户决定）

§22.3 发现「两次同格复读一致」不等于读对：Vision 旧图 85% 的一条股票期权 CALL，DAILY P&L 首读（三位整数、末位为 0）正确，
3×/4× 两次都丢掉末位 0 并被采用。用户决定：**首读合法、两次同格复读一致但数值不同（含正负号不同）时，
两者都不采用，保持未知，并在疑点里列出两种读数**。适用于 Q3 的 Vision 字段和 DAILY P&L。

- 代码：`numericChecks` 的 `replaced` / `sign_conflict` 合并为 `reread_conflict`；字段证据新增
  `conflictingReadings: {first, reread}`；疑点文字为「<字段> 首读 X 与两次同格放大读数 Y 不一致

| 机器更改 | 格式等价的价格排版不进入单独批量确认；真实更正、数量补读、合约推断仍保留确认与证据 |
| 结构 / 现金 | 组合完整性、父子范围、错位拒收、排除与现金校核规则保持 |
