## 跟进复核与修正（同日）

复核时发现，上面的提交门禁检查的是"导入后整本账本"的全部回放告警。账本里已有的告警因此会禁用之后所有无关导入：例如持有期权时登记的拆股（后台接受，前端提示 `split_crosses_open_option`），或旧版迁移中允许超额的平仓。批量归账还有两类记录不显示：股票/期货往返成交，以及没有持仓差额、只作为问题行出现的成交（例如佣金未到齐）。

修正：

- 预览分别给出导入前后的回放告警，按出现次数比较，得到"本次导入新增"（`newWarnings`）。只有本次新增、且属于后台必然拒绝写入的错误才阻断：无开仓支持的平仓、无效 C/O、O 行反向、FUT 换月超量、期权合约身份歧义、FUT 合约身份冲突、拆股比例无效。
- 账本原有告警，以及拆股跨越未平仓期权、合约身份提示等建议性告警，只提示、不阻断。预览区分"本次错误 / 本次提示 / 账本原有提示"三类显示，确认弹窗也列出不阻断的提示。
- 批量归账把未归账的股票/期货成交（笔数、净数量、含返佣净现金），以及未归入任何差额的问题成交都列入待处理。其他标的的问题行不列入。

验证：`node tests/run.js` **1172 通过，0 失败**；账本 Python **277 项，2 项因环境/本地报表跳过**；资源版本检查通过。新增覆盖：已存拆股告警下无关股票导入可提交且弹窗含提示；同一合约第二笔无开仓平仓仍阻断；股票往返与佣金未到齐的往返列入待处理。浏览器脚本已同步为模拟"本次新增"错误；本机未安装 Playwright，未重新执行。
