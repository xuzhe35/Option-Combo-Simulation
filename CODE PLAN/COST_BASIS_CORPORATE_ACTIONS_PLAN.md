## 2. 已核实规则与交付范围

### 2.1 公告规则、精确舍入与调整类

OCC #57592 指定 TQQQ 2025-11-20 生效，合约张数乘 2、行权价除数 2，报价乘数仍为 100。表格列出发布时的系列，发布后至生效前新增的系列也使用公告除数；**规则可以生成新行权价，不要求每个系列先出现在表格里**。公告同时列出 `TQQQ` 和 `2TQQQ`，两种根代码均保留。[OCC #57592（MIAX 镜像）](https://www.miaxglobal.com/sites/default/files/alert-files/TQQQ_Split_57592.pdf)

本公告行权价算法固定为：将原十进制行权价精确转为整数分 `c`，对正整数除数 `n` 做整数除法，`q = c div n`、`r = c mod n`；若 `2r >= n`，结果分数为 `q + 1`，否则为 `q`。JS 用整数／BigInt，Python 用整数；不能先做浮点除法或用 `toFixed` 决定经济值。输入多余小数位只可精确消去尾零，不能先把未知精度行权价四舍五入到分。

本次独立核对了公告全部 **167 对**行权价，全部符合上述半数进位算法；其中 `99.97 → 49.99`、`105.05 → 52.53`、`106.49 → 53.25` 是除以 2 后需要半分进位的三例，浮点 `(k/2).toFixed(2)` 三例均错误。公告明确给出除数，半数进位是本次由完整表核实并冻结的实现规则，不声称原文逐字写出了该算法，也不将它外推为所有未来公告的通用规则。[同一公告的行权价表及表后说明](https://www.miaxglobal.com/sites/default/files/alert-files/TQQQ_Split_57592.pdf)

`2TQQQ` 是必须保留身份的既有调整类，不能去掉数字前缀后套用标准合约假设。A 线根据期权根代码、tradingClass、券商身份及已有调整记录确认标准资格；`2TQQQ`、身份冲突或标准资格无法证明的系列进入明确的不支持／缺项流程。不能仅凭同属 TQQQ、乘数为 100 或公告列有该根代码就放行。

本次规则基线为 #57592；其他历史公告或未来规则须分别核实适用类别、比例、精度与舍入，不硬编码“所有 TQQQ 永远照此处理”。

### 2.2 A、B 两条线

| 工作线 | 范围 | 交付与边界 |
| --- | --- | --- |
| **A：优先实施** | 有明确规则的标准整数正向拆股 `n:1`，股票数量与标准期权张数乘 n、行权价按规则除 n、乘数及标准交割单位不变 | 识别、回放、后端校验、追加／重建、TWS 对账、下游计算和备份闭环；2:1、3:1、连续拆股、多空与部分平仓均覆盖 |
| **A：异常处理必需** | 非标准类、未知格式、证据不足、修订冲突 | 逐项说明；本批含不能处理的行动则不部分写入，不丢行、不猜条款 |
| **B：暂不启动** | 反向／非整数拆股、非标准交割包、现金替代及其待结算权益 | 有实际持仓或报表需求并取得资料后另行细化，不牵制 A 线交付 |
| **本计划范围外** | 合并、多证券换股、跨币种交割篮子、FOP/FUT 公司行动 | 保留明确的不支持结果，不能套用股票规则 |

A 线不需要先建设 `ContractTerms v2`、通用公司行动 JSON 引擎、持久化草稿表或现金替代子系统。整数正向拆股不因比例本身产生新的不足一股余数；已有碎股按精确数量扩大，若实际报表另有碎股处置或现金调整，则超出 A 线，不能将其款项忽略。

A 线完成自己的 P0–P5 后可明确发布“支持经核实的标准整数正向拆股”；不等待 B 线，也不宣称支持全部公司行动。

## 3. 不变式

1. 账本是事实来源；TWS 快照只发现差异，不能自动产生拆股或成交事件。
2. 拆股不是买卖：现金、费用为零；未平权利金承接到新系列，不在拆股日提前实现。
3. 无现金的 A 线转换保持总现金、股票各成本口径的总成本、未实现权利金和既有已实现损益；每股／每张分摊按新数量变化。
4. 指派／行权只记录股票交割本金；权利金不能再次收付。历史交易数量、价格、日期和券商引用不改写成复权值。
5. 同一账户一次行动的股票调整和全部适用期权转换属于原子组；不能选一半腿提交或单独排除一腿后仍记为完整。
6. 转出必须消耗生效前旧系列的全部未平仓，转出后旧余额恰好为零；转入保留原多空方向，数量按 n 倍增长。
7. 重复、跨格式、TWS 重叠和重试只应用一次行动；补录早期历史也必须重新验证后续行动。
8. 旧提示不阻断无关导入；本次确实依赖未解决条款时，显示具体原因，不能输出“已完整核对”。
9. 行动、来源、转换关系、人工核实及替代历史均可审计；金额一致不能替代合约身份和顺序的证据。

## 4. A 线的最小数据模型

### 4.1 正式列与原子组

沿用 `futures_roll` 的显式新旧合约字段思路，保留 `split` 表示股票比例调整，新增 `option_split` 表示一条旧期权系列的转出及对应新系列的转入。它是专用记账种类，不伪装成普通 `option_trade`。股票与各系列行通过同一个 `split_group_id` 原子提交；即使没有股票持仓，也可有期权转换组。

拟议正式列及关系如下，P1 固定完整 DDL、类型、CHECK 和索引后实施：

| 位置 | 字段／语义 |
| --- | --- |
| `cost_basis_split_groups`（新） | 组 ID、book/account、经济行动键、整数比例 n（n ≥ 2，分母固定为 1）、生效日、阶段／同日行动顺序、适用根代码／规则 ID 和版本、精度与舍入方式、来源摘要 |
| 事件表的关联与排序 | `split_group_id`、`effective_phase`；普通旧事件默认普通阶段，不改变其历史排序 |
| `option_split` 的旧系列 | 复用账户、C/P、到期日、strike、conId、localSymbol、sharesPerContract；补充显式 `option_root`、`trading_class`，不得从标的名抹去调整类 |
| `option_split` 的数量及精度 | `contracts` 为旧系列有符号转出增量；`split_to_contracts` 为新系列有符号转入增量；`split_from_strike_cents`、`split_to_strike_cents` 保存本规则的精确整数分，与旧字段严格核对 |
| `option_split` 的目的身份 | `split_to_con_id`、`split_to_local_symbol`、`split_to_option_root`、`split_to_trading_class`；C/P、到期日、乘数在 A 线保持不变，不开放任意改条款 |
| `cost_basis_event_source_refs`（新或等价正规化关系） | 原始引用、来源命名空间、内容摘要及对应事件／组；保留行号、原始报告时间等旁证，不用备注充当经济排序字段 |
| 旧股票调整关联 | 组可引用一条已核实等价的 legacy `split`；此关联代表“股票腿已有”，不能再应用一次比例；语义见 §9.2 |

组级字段不得在各腿保存互相矛盾的副本；外键、唯一约束和后端校验保证一致。规则必须有明确来源及可离线重放的冻结参数；以后发布的新规则不能改变已入账历史。

新行动组和新股票／期权腿必须显式绑定账户；空账户只保留给既有 legacy `split` 及其受约束的兼容处理。股票腿与组比例、生效边界及来源数量也须核对，不能只验证期权后忽略股票的重复调整。

A 线不使用 `corporate_action_json`、`contract_terms_json`、`effective_order_json` 承载经济字段。辅助证据可以保存原文，但比例、数量、身份和排序均须可直接查询、验证、参与摘要及备份。

### 4.2 数量约定与身份

设旧余额为有符号 `p`、旧系列转出增量为 `out`、新系列转入增量为 `incoming`。必须满足 `out = -p`、`p + out = 0`、`incoming = p × n = -out × n`。因此“转入张数等于转出张数乘 n”指绝对数量，不是两个账本增量同号。例如旧空头 -2，转出 +2，新空头转入 -4。

源和目的系列按生效边界关联，不建立永久相等别名。缺失 conId 不得伪造；结构匹配只在根代码、类别、条款及可用券商身份唯一一致时成立。相同可见条款的不同合约不能净额混在一起；相同 conId 也不能掩盖冲突条款。

A 线继续使用已证明标准合约的现有乘数及交割模型。报价乘数与交割包分离属于 B 线；A 线遇到相关反例必须拒绝，不能偷偷放宽标准资格。

## 5. 回放、后端校验与排序

### 5.1 回放与成本承接

回放到生效边界，冻结全部旧持仓。股票数量乘 n、各总成本不变。每条 `option_split` 只转移尚未平仓的张数、`openPremium` 和 `openShortPremium`；既有已实现桶及 realization 日期保留。

后端可以复用平仓／开仓的**数量合法性检查**，但核心不得调用普通平仓的**收益实现函数**。需要专用余额及权利金转移函数，现金和费用均为零。后续平仓或指派才按既有规则实现／分摊承接的权利金。

同一组先验证并转出全部旧余额，再统一转入目的系列。不能遍历一腿就立即把它的新余额当下一腿的旧余额；例如旧 K100→K50、旧 K50→K25 同时存在时，不得把第一腿转来的 K50 再拆一次。内部投影保留行动前／后的身份区间，界面只见完整组。

手算例（合成交易）：买 100 股×80，另卖 2 张 K100 Put、乘数 100、权利金报价 4；2:1 后为 200 股、每股成本 40、空头 4 张 K50、未实现权利金仍 800。回补新合约 1 张、报价 1、费用 1，现金 -101、实现净收益 99，剩余权利金 600。再指派 1 张，增加 100 股、交割现金 -5,000，余 2 张权利金 400。分摊到指派的 200 按既有税务口径进入成本，不再收一次现金。

### 5.2 在原有校验上补齐跨键约束

复用逐合约时间线，将 `option_split` 投影为两个数量动作：源键的严格平仓和目的键的严格开仓；不把投影保存成普通成交。在现有框架旁增加 `_validate_option_split_timeline`（拟名），参照 `_validate_futures_timeline` 做账户范围的行动组校验，不另建通用公司行动回放引擎。

后端每次必须独立检查：

1. 组的账户、标的、币种、日期、整数比例、标准资格及规则一致；不能信任前端“已校验”标记。
2. 每个源系列转出方向正确、不超额，而且**转出后恰好归零**；一般平仓“没有超额”不足以证明全量转换。
3. `incoming = -out × n`；目的行权价等于精确舍入规则结果，C/P、到期日、乘数保持不变，目的身份无矛盾。
4. 冻结的所有适用未平系列都有且仅有一条转换；缺掉整腿或把旧余额留在未列出的系列也失败。零余额不得产生无来源的新仓。
5. 完整组先清源再入目的；目的开仓按同一标准系列核对。相反方向或多身份合并不由净数量强行证明。
6. 后续平仓／交割仍有足够的新系列余额；纯 C、纯 O、C/O 原有规则继续执行。

追加、补录、冲销、includeInCost 排除、批量、重建和恢复都经过这些检查。历史写入必须找出该账户自变更日以后受影响的拆股组并复验，不能只检查新行所属合约。例：组记录旧 -2→新 -4，后来在拆前补卖 1 张，旧余额变成 -3；原转出 +2 留下 -1，后端必须拒绝，直至同一修复事务把组改为转出 +3／转入 -6，并验证后续历史。

### 5.3 五处排序统一到同一契约

A 线明确盘前生效的行动使用阶段键。统一经济排序为 `(trade_date, effective_phase, 同日行动顺序, 该阶段时间键, seq)`；普通事件默认同一普通阶段和顺序，保留现有 `trade_date → broker_timestamp（缺失按日末）→ seq`。拆股组在生效日普通拆后交易前原子应用。已证明属于行动前的同日记录可有前置阶段；无法证明单位或先后时阻断，不按文件到达顺序猜测。同日多个行动没有顺序证据也不能默认排序。

后端须根据已冻结的行动规则和来源证据核验阶段，不能接受客户端任意改阶段，把原本缺开仓的平仓移动到另一边来绕过校验。组内同一生效阶段先完成全部转出再转入，普通事件不能插入组中间。

| 必改位置 | 要求 |
| --- | --- |
| `js/cost_basis_core.js::_sortEvents` | 使用统一经济键，按组冻结源余额、应用转换 |
| `js/cost_basis_import.js::_sortStamp` 及其排序调用点 | 不再仅比较 brokerTimestamp；必须先 trade_date，再阶段及其余键 |
| `js/cost_basis.js::_eventTimestamp` 及其基线／cutoff 比较调用点 | 真实时间显示保留；经济筛选另用同一排序／阶段比较器，不能把阶段伪装成券商时间 |
| `cost_basis_store.py::_EVENT_ORDER_SQL` 及同类内联 ORDER BY | 与 JS 一致；源／目的投影服从相同组边界 |
| `js/cost_basis_import.js::_classifySplitReversals` | 同一经济键，且纳入拆股两腿；不能仍过滤成只有普通 contracts 行而遗漏转换 |

将 JS 比较器提为 DOM-free 共用函数，Python／SQL 通过共同测试向量核验等价。券商 Report Date 和原始 Date/Time 保留为来源，不自动当成除权生效时点；不伪造午夜成交时间。增加跨语言顺序测试，逐事件 ID 比对五条路径，覆盖 trade_date 与时间字符串不一致、缺秒、日末、同秒 seq、盘前转换、旧版 split 和 C/O 分笔。

## 6. 报表证据与导入流程

### 6.1 P0 是解析实现的硬门槛

**开始实现公司行动解析前，必须取得跨 2025-11-20 的真实 Activity 与 Flex 导出，脱敏保存并核对。当前这些样本尚未在本计划中得到确认。** P0 同时记录用户是否需要补导 2025 年历史、所持系列是否包含调整类，或当前需求仅是为未来标准拆股做准备。已有 2026 年文件不作为跨该边界的证据。

P0 产物是输入格式说明与脱敏 fixture：各格式的真实段名／表头、账户与标的、报告时间／生效时间、来源引用、数量含义、是否存在逐期权系列调整行、汇总／明细关系及期初期末证据。先确认这些事实，再固定解析映射和分组规则。公开字段说明、人工合成报表或仅股票公告不能替代真实导出。

已有证券识别修复继续保留，属于已完成前置工作。它只决定某行是否与本标的有关，不证明账户、行动类型、数量语义、系列标准资格及拆股条款均已核实。

解析器的后续设计只设条件，不预设券商形态：

- 若真实文件有逐系列出入库行，证明各腿与规则、旧余额一致后分组；汇总与明细不能重复计数。
- 若只有股票公司行动行、期权调整体现在期末仓位，依据已核实行动规则与拆前标准期权余额生成转换，再对期末和可用的拆后成交核验。不能制造“缺失的券商期权行”，来源应标为规则推导。
- 若两者同时存在，则互相核对；冲突不得择一忽略。缺少确切行动／类别／时点证明时保留问题。

没有真实样本时可进行数学与数量校验的独立原型，但不实现未经证实的 §6 解析规则，不开放相应 CSV 成功导入，也不宣布 A 线完成。

### 6.2 期初、去重和部分重叠

期初按分段行动时间线推导。最简单的一次 2:1 情况是“期末 = 2 × 拆股前余额 + 拆后净变动”；不能直接用期末减全期成交数量。期权先沿明确系列关系换算，缺映射或成本证据不制造零成本开仓。仅拆后报表的已证明期初属于拆后单位，区间外行动不再应用。

先有拆后期初存根、后补早期历史，须证明转换后的余额和可归属成本完整一致，再同事务替换。任何补录同时触发 §5.2 的后续组归零／比例／完整性检查。

同一行动跨月报、年报、Activity、Flex 只应用一次：行动键使用经济身份及核实关联，文件摘要只绑定本次预览；原事务／系列行引用通过来源关系保存。同引用的比例、时点、目的身份或数量变化是修订冲突，不能当新行动，也不能无条件跳过。缺乏共同引用的疑似重复必须展示待核对。

TWS 原始成交按当时单位、身份和经济字段匹配报表；拆股本身不冒充成交。保留“Order＋Trade 子行＋部分 TWS 重叠＋C/O＋拆股”联合路径，剩余分笔在包含转换的完整时间线上重标纯平、穿零或纯开。

追加与整本重建使用相同规则和回放语义；重建不因旧账本中的重复引用遗漏文件历史。无成交月份仍检查行动和期末持仓，草稿为 0 不能代替完整性证明。

## 7. A 线用户流程与 TWS

CSV 预览增加行动分组，显示生效日、比例／规则来源、股票前后数量与成本、旧期权→新期权、张数、行权价及承接权利金。证据齐全后一并确认入账；非标准类和缺项列出具体原行、原因及需补的资料，整批未解决则不写部分账本。

A 线复用已有导入预览状态：补充证据或修改映射后重新预览，不新增持久化草稿表。规则生成的行权价可直接使用，但券商身份、期末或成交与规则矛盾时必须解决后才能提交。

TWS 单笔、普通拉取和批量归账统一遵循：

1. 以账本已确认转换后的当前余额对账；快照中股数翻倍、新旧期权变化只能提示疑似缺行动，不能自动写账。
2. 批量查找保留“公司行动待核对”，引导补报表／规则；不能用虚假成交、期初存根或默认合约消除差额。
3. 行动已在账本确认，或在本次同一原子批次中得到完整验证后，可匹配拆后新系列的成交，避免必须先单独写行动的操作死锁。
4. 预览绑定账本版本、规则／组摘要、账户和持仓内容指纹；仅广播时间戳变化不使其过期，数量／身份变化或断线则重新预览。
5. 股票、期权、FUT 的零净持仓往返及缺佣金问题继续展示；加入行动分组不能重新丢失这些记录。

保留一次确认、原子归账；不增加交易通道、自动记账或持续行情订阅。无 TWS 时 CSV 和本地回放可用，未获得实时身份旁证则如实显示。

## 8. A 线下游计算与 B 线边界

标准转换后的 `openOptions`、数量、行权价和未实现权利金直接供卖方到期表、What If 和压力测试使用；历史收益日期不变。缓存、异步 worker 和报价匹配绑定行动组／账本摘要，旧持仓或旧价不能配新数量。

验收标准合约在相同经济时点、价格按 `S/n` 转换时的经济等价。无行权价舍入的例子可严格比较；有舍入的例子按实际新 K 计算，不能强行要求未舍入的本金／价值恒等式。未来股价、IV 等行情变化与拆股记账区分开。

非标准类或无法证明条款的腿不能套标准 BSM／CRR、按零估值或沿用旧图；完整组合结果明确不可用。旧拆股提示本身不阻断无关导入，但不能让依赖未解决期权的结果显示已核实。

B 线在实际需求明确后另定：报价乘数／行权本金／交割股数／交割现金的独立模型、反向与非整数比例、碎股权益及到账、非标准到期收益与到期前估值边界。`ContractTerms v2`、`cash_in_lieu`、草稿持久化等仅是 B 线候选，不在 A 线预建，不沿用本次撤回的通用 JSON 方案作为既定实现。

## 9. 事务、旧 split、迁移与恢复

### 9.1 写入与版本

复用现有 `import_cost_basis_events`、重建、恢复事务以及完整 bookIdentity、expectedLedgerVersion、固定幂等 token。正式列、行动组和来源关系全部参与账本摘要；后端在写锁内执行 §5.2。组内失败回滚事件、来源、覆盖与存档。未知规则／协议版本拒绝，旧客户端遇新事件要求更新，不能漏算后照常显示。

修改受影响历史使相关日期起的覆盖证明失效；重导只有完成该报表检查才重新登记。冲销或排除组内单腿、原开仓或已被依赖的转换时必须复验完整组；需要修复时以显式替代计划在同事务处理，不能用 allow_overdraw 绕开行动约束。

### 9.2 旧版整本 split 的精确兼容

旧 `split` 的 account 为空时，`bookWideSplit` 会作用于生效点之前已在回放中的各账户；它不是一个“空账户”，也不等于当前账本标题选中的单账户。保留这种读取和账户筛选语义，schema 升级不自动拆分或重写旧行。

修复或与 CSV 关联时先按旧排序回放，列明当时受影响的账户集合及每账户的股数／成本前后值；不能用今天的账户清单代替，也不能让后来出现的账户追溯获得一次拆股。

- 仅一个有效账户，且比例和经济生效边界与新证据一致：可在账户行动组中引用旧股票腿，新增期权转换和来源证明，不再生成股票调整。
- 旧行整本作用于多个账户：来源／组关联必须按“旧事件 ID＋实际受影响账户”记录，保留原行一次执行；某一账户已核对不代表其他账户也核对。
- 若旧日末顺序与新盘前边界不一致，或旧比例本身错误，不能直接认作等价。明确预览替代影响，将旧整本行作废，并在同事务为全部受影响账户保留或修复其股票调整；非本次账户的原经济效果也须核平。
- 账户归属或其他账户历史无法证明时，拒绝该替代操作；不自动把旧整本行改成单账户，也不先作废再让其余账户丢失调整。

混合账户遗留账本保持可读；新功能不得扩大其普通跨账户写入权限。涉及多账户的旧行替代只能通过受约束的遗留修复事务进行。

### 9.3 迁移、存档与备份

使用下一个未占用 schema 版本；扩展 CHECK 和正式列／表在一次迁移事务中完成，重建必要索引。旧 split 和旧交易不因升级改变经济含义。

行动组、来源关联及旧行替代链随重建／清空存档，恢复时校验摘要并完整恢复；永久删除清理对应关系。JSON 备份升级保存新数据，保留旧 v1 兼容分支但不把旧提示升级成已核实映射。审计 CSV 单列调整组与两腿，不伪装成交易。分页、导出、备份、恢复和协议都必须传递新增字段。

Live／Historical 仍挂载相同存储和协议。保持 payload／WebSocket 上限；过大批次在预览阶段报明，不能拆成多次可见的半组。测试在临时数据库进行，不修改真实账本；应用回退须明确 schema／备份兼容，旧版本不能静默忽略新事件。

### 11.2 针对拆股路径的随机测试

继续使用不调用生产代码的 Python Fraction 独立模型，按经济历史独立生成规则、预期余额及已经由 P0 证实的报表结构。每组至少包含一个标准拆股，轮换多空、部分平仓、连续行动、提前补录、旧整本行、缺腿、重复、回滚及恢复。专用分支强制生成 A11 的五项联合条件，不能只靠随机偶遇。

A 线门槛：固定矩阵全通过、公告完整表向量通过；CI 100 个固定种子（至少 20 个穿过临时 SQLite），合并前至少 500 个拆股专用种子（至少 100 个走完整数据库），其中至少 100 个种子此前未使用。按矩阵统计命中，任何必测分支未命中仍失败。数量是最低执行量，不是正确性证明；失败保留种子、阶段、输入和重跑命令，缩减后加入永久反例。

变形检查包含完整导入／合法分批／TWS 后补月报／重建／备份恢复结果一致，坏批次完整 DB 摘要不变。同一规则下仅在无舍入且精确可逆的合成转换中检查逆变换；该数学检查不代表 A 线支持真实反向拆股。

原来的 10,000 种子／1,000 数据库规模可在 B 线立项后根据范围重新评估，不再作为 A 线合并门槛。随机数量不得替代真实格式和缺项恢复验收。

### 11.3 证据隔离与报告

P0 真实跨拆股的 Activity、Flex 样本必须脱敏或仅在本机显式配置，不上传完整私人账单。现有 2026 年报表只验证原路径，不证明 2025-11-20 的转换。缺少真实样本就记录 P0 未完成，不以合成样本充当正式格式验收。

自动写入只使用临时 SQLite；浏览器拦截网络或连接隔离后端，不发真实订单。执行既有 JS 全套、账本 Python 全套、新增专项与隔离浏览器回归；分别报告失败、跳过、缺样本和未覆盖项。本次文档修订核对的 167 对行权价及现有 3 项公司行动识别测试，不算尚未实现功能的测试成绩。

实施时同步 README、ARCHITECTURE、DEV_HANDOVER、账本主设计、导入完整性和随机回归的当前行为；压力测试仅更新实际受影响段落。发布记录实际 schema／备份版本、测试结果、样本范围、未完成项及回退方案。B 线只有在确认真实需求并另行审核其数据与测试方案后启动。

## 13. 审计意见（2026-09-23）

> 以下审计原文保留作历史记录，其中章节号指修订前版本；本次处理结果见 §14。不得把原文中的旧设计要求当作当前实施门槛。

审计范围：对照当前代码与 OCC #57592 原文（经 [MIAX 镜像](https://www.miaxglobal.com/sites/default/files/alert-files/TQQQ_Split_57592.pdf) 读取，OCC 站点直连返回 403）核对本计划。第 3 节不变式、"拆股不是买卖"、转换不得走普通平仓分摊、原始成交不改写及原子写入等原则正确，下列各项不重复肯定部分，只列错误与遗漏。

### 13.1 事实或规则错误

1. **"公式只生成候选"与 OCC 规则不符（§2.1）。** 公告写明行权价表只列发布时已挂牌的系列，之后新增的系列"will be adjusted using the strike divisor stated above"。因此"除数 + 舍入"本身就是规则，表格是它的枚举，不能反过来把公式降为候选、要求逐系列明确条款。应改为：以公告的除数和舍入规则为准，用公告表做测试向量，券商实际成交/持仓作为核对证据。
2. **没有写出舍入算法，而默认浮点写法会算错（§2.1、§11.1 S07）。** 公告为按分四舍五入（半数进位）：`99.97 → 49.99`、`105.05 → 52.53`、`106.49 → 53.25`。公告全表 167 个系列中，除以 2 后不是整分的只有这 3 个。实测 `(k/2).toFixed(2)` 在这 3 个上全部算错（49.98、52.52、53.24）；"整数分 + 半数进位"与全表 167 行全部一致。计划必须规定"行权价先转为整数分，再做有理数除法和半数进位"，并把公告全表列为固定向量。
3. **遗漏 `2TQQQ` 调整类（§2.1、§4.2）。** 公告标题为 "Option Symbols: TQQQ/2TQQQ"，正文写 "2TQQQ remains 2TQQQ"，即同一次拆股还调整了一个既有的非标准期权类。计划只描述了标准类的条款（乘 2、除 2、交割 100 股），没有提到该类。任何只支持标准调整的实现都必须按期权根代码/交易类别识别这类合约，并阻断或进入缺项流程，不能按标准条款转换。
4. **§1 对现有 `_corporateActionProblems` 的描述不准确。** 原实现是对整行文本做子串匹配（`indexOf`），不是"本标的公司行动一律阻断"：它同时会误伤其他标的。IBKR 描述里带发行人全名，如 `TQQQ(US74347X8314) Split 2 for 1 (TQQQ, PROSHARES ULTRAPRO QQQ, …)`，QQQ 账本会因 TQQQ、SQQQ、QQQM 的公司行动被整批阻断。**已于 2026-09-23 单独修复**：取行首证券代码（`代码(ISIN)` 或期权"根代码 到期 行权价 C/P"）或显式代码列比较；`2TQQQ` 这类数字前缀调整类算同一标的；认不出格式时只要整词提到本标的仍阻断。回归见 `tests/cost_basis_import.test.js` 中 "corporate actions match the instrument a row names…"。§6.1 第 1 步可据此改为"已完成的前置修复"。

### 13.2 设计上的错误或缺口

5. **范围门槛设错（§2.2 末段、§12）。** 要求 TQQQ 标准拆股"至少完成 P0–P6"才可宣称支持。但整数正向拆股（n:1、期权张数乘 n、行权价除 n、乘数不变）既不产生碎股、也不需要非标准交割包，所以现金替代、`ContractTerms v2`、反向/非整数拆股、草稿表都不是它的前置条件。S01 把 2:1 与 3:2、1:5 放在同一格也掩盖了这一点。应拆成两条线：
   - A 线：标准整数正向拆股的完整闭环，含识别、回放、后端校验、TWS 提示、下游估值；遇到非标准类则阻断。
   - B 线：非标准交割、反向与非整数拆股、现金替代。有真实需求再做。
6. **§6.1 的解析设计缺乏证据，却排在证据收集之前。** IBKR 如何在 Activity/Flex 中表示期权调整尚未确认：可能每个系列都有出入库行，也可能只有股票行、期权只体现在持仓变化上。§6.1 的步骤已经预设了"原证券减少／新证券增加"等形态。P0 应改为硬门槛：先取得跨 2025-11-20 的真实 Activity 与 Flex 导出并脱敏存档，据实写解析规则；在此之前不应实现 §6.1。
7. **转换的后端校验漏掉关键检查，同时把方案做大了（§4.1、§5.2）。** 更简单且正确的做法：把转换表示为旧系列上的"转出"（按平仓校验）和新系列上的"转入"（按开仓校验），外加两条跨键检查：
   - 转出后旧系列必须**正好归零**；
   - 转入张数 = 转出张数 × n。

   这样现有逐合约回放基本够用。计划只写了"补入早期历史改变边界余额时需要重新解析"，没有说后端如何发现这种情况；没有"必须归零"检查时，回补一笔拆股前的开仓会在旧系列留下残余，而逐合约的平仓超额检查发现不了。仓库已有同构先例：`futures_roll` 用正式列（`roll_to_expiry`、`roll_to_con_id`、`roll_group`）表示新旧合约，由 `_validate_futures_timeline` 做账户级校验。建议沿用正式列，而不是 `corporate_action_json`、`contract_terms_json`、`effective_order_json` 三个 JSON 字段：后者需要另写一套白名单校验，且后端 SQL 时间线核对无法直接查询。
8. **排序改动没有落到具体位置（§5.2）。** 至少有 5 处独立排序实现需要同时加入"除权日开盘前生效"的阶段键：
   - 核心 `_sortEvents`
   - 导入 `_sortStamp`
   - 页面 `_eventTimestamp`
   - 后端 `_EVENT_ORDER_SQL`
   - 分笔重标 `_classifySplitReversals`

   其中 `_sortStamp` 已与 `_EVENT_ORDER_SQL` 不同（后者先按 `trade_date` 排）。此前 C/O 分笔问题正属于排序/标签不一致一类。计划应逐一列出，并加一个 JS 与 Python 的排序一致性测试。
9. **旧 `split` 的兼容说明遗漏"整本生效"语义（§4.1、§9.2）。** 当前 `split` 不填账户时对账本内所有账户生效（核心 `bookWideSplit`），而新复合事件按账户生效。迁移/修复旧记录时必须说明整本 `split` 如何对应到各账户，否则"股票比例不能应用两次"（§6.3）无法判断。

### 13.3 前提与优先级

10. **需求前提未核实（§0、§11.3）。** 09-14 记录中导入的全年报表从 2026-01-01 开始，晚于 2025-11-20；计划自己也承认 2026 年报表不能证明覆盖该边界。计划没有指出哪份真实报表需要跨拆股导入。若只是为了补导 2025 年历史或应对未来拆股，应据此排定 A 线的优先级；B 线在没有实际持有非标准合约之前不应启动。
11. **验收门槛与阶段不匹配（§11.2）。** "合并前 10,000 个种子、1,000 个走完整数据库"适合 B 线完成时。A 线用固定矩阵、OCC 公告表向量和专门覆盖拆股路径的随机生成器即可，避免门槛本身成为长期不交付的理由。

未核实项：§2.1 引用的 OCC #49829（2022-01-13 拆股）与 IBKR 公司行动字段说明，本次审计未读原文，结论不依赖它们。

## 15. 第二轮审计与 A1 决定（2026-09-23）

> 本节在 §14 修订后的正文上做第二轮审计，并记录用户决定；与 §1–12 冲突时以本节为准。所有模拟只用合成数据、临时 SQLite，未读写真实账本。

### 15.1 用户决定

1. 没有需要跨 2025-11-20 导入的报表，不补导 2025 年历史。
2. 先做 **A1：手工拆股（含期权转换）**。报表解析另列为 **A2**，保留 §6.1 的 P0 门槛，出现真实跨边界报表时再启动。
3. A1 不依赖真实报表，用合成的模拟场景验证代码（§15.5）。§6.1 末段、§11.3、§12 中"缺真实样本就不宣布 A 线完成"只约束 A2。
4. 规则来源是每次拆股的 OCC 信息备忘录。OCC 对每次合约调整都发布备忘录，写明比例、行权价除数、生效日、适用期权代码，并附发布时的行权价表；TQQQ 本次为 #57592（§2.1 已核对原文与全表）。A1 录入备忘录编号、整数比例 n 和生效日，系统按 §2.1 的整数分算法推导新行权价，预览逐系列列出旧→新，供对照备忘录表格确认。A1 只支持"整数分、半数进位"一种舍入方式；备忘录写明其他舍入、非标准交割或调整类时，不属于 A1。

### 15.2 A1 的范围与流程

1. 手工录入的"拆股"改为创建行动组：填写账户、生效日（除权日）、n、备忘录编号。只有股票、没有期权时也建组。旧的单行 `split` 不再能新建，已有行照常读取和计算。
2. 系统回放到生效日开盘前，列出该账户股票数量与成本的前后值，以及每个适用未平期权系列的旧→新：张数、行权价、承接的权利金。
3. 以下系列列为缺项，整组不能提交：根代码不是本标的（如 `2TQQQ`）、源行权价不是整分、同组两个旧系列推导到同一新行权价。所有行都没有 `local_symbol` 的系列（手工行）显示为"未证明标准类"，须逐系列勾选确认，确认结果记录在该条转换上。
4. 确认后原子写入股票腿和每个系列一条 `option_split`；后端独立执行 §5.2 的全部检查。
5. 该账户在同一生效日已有有效的旧 `split`（含不带账户的整本行）时，A1 拒绝建组并说明原因；§9.2 的旧行替代流程推迟到 A2 或单独需求。
6. TWS 对账、卖方到期表、What If、压力测试直接使用回放后的持仓，不另建入口；TWS 快照差异仍只提示，不自动写账。

### 15.3 实施前必须补上的设计（本轮审计，均已用模拟复现）

1. **身份键缺少"拆股代次"。** 2:1 拆股后旧 K100 变成 K50、旧 K50 变成 K25，所以拆前与拆后的 K50 是两份合约，但结构键（账户、看涨看跌、行权价、到期日、每张股数）和 OCC 本地代码完全相同。前端核心 `_buildIdentityResolution`、导入 `_resolvePositionIdentities`、后端 `_resolve_contract_identity_rows` 都对整条时间线一次性分组，拆前拆后的合约编号落在同一组里。模拟 S1、S1b 证实：拆后一笔没有 conId 的平仓被后端直接拒绝写入；前端报 `contract_identity_ambiguous`（阻断级），并把这笔平仓记成一个身份不明的多头，真实空头仍显示未平。去掉拆前历史后，同样两行完全正常。要求：三处身份识别及后端按行权价查询的时间线校验（`_validate_timeline`、`_validate_contract_timeline`、`_validate_batch_timelines`）都按"该账户在此事件之前已应用的拆股组数"分代。IBKR 在拆股前后是否沿用合约编号目前未知，分代设计在沿用与不沿用两种情况下都必须成立。
2. **转换行需要统一的展开函数。** `option_split` 沿用 `right`、`strike`、`contracts` 字段，现有按期权类型或"有张数、有看涨看跌"筛选的代码只会看到转出一侧：核心约 9 处、后端约 11 处引用期权类型，后端至少还有 3 处写死的事件类型列表，`cost_basis.js` 约 15 处按合约键匹配，`_classifySplitReversals` 也按这些字段过滤。后端 `_net_short_share_warnings` 自己回放旧拆股，也要认得新组的股票腿。要求：JS 与 Python 各提供一个展开函数，把一条转换展开为两条带方向的数量变动；P1 交付完整的使用方清单，并加测试检测直接读取未展开转换行的代码。
3. **旧 `split` 按日末排序，会重复放大除权日当天的交易（现有缺陷）。** 模拟 S2：拆前 100 股，旧 `split` 填除权日，当天 10:00 拆后再买 100 股，账本得 400 股，正确应为 300 股，且没有任何提示。A1 的新组排在交易日开盘前，不再有此问题；旧行的经济含义不能改（§9.3），应增加提示：旧 `split` 所在交易日存在其他事件时，显示"可能按拆前单位重复放大，请核对"，只提示、不阻断。

### 15.4 P1 前已定的设计

1. **排序只用两个阶段。** 拆股组排在其交易日最前，普通事件在后。阶段存放在事件表上，因为 `_EVENT_ORDER_SQL` 被 6 处不带关联的查询使用；这是 §4.1"组级字段不在各行保存副本"的明确例外，由后端在写入时核对与组一致。同一账户同一交易日只允许一个拆股组；普通事件不能设置阶段。取消 §5.3 的"同日行动顺序"和普通事件的"前置阶段"。
2. **"适用未平系列"只包括到期日不早于生效日的系列。** 已过期但漏记到期的系列不转换，作为已有问题提示，不阻断建组。
3. **精简数据模型。**
   - 去掉 `split_from_strike_cents`（与 `strike` 重复）；源行权价由 `strike` 精确换算为整分，不是整分即不属于 A1。
   - A1 不建 `cost_basis_event_source_refs`，各行沿用现有 `source`、`external_ref`。
   - 根代码从现有 `local_symbol` 推出：报表格式 `TQQQ 19DEC25 100 P` 与 OCC 格式 `TQQQ  251219P00100000` 都以根代码开头；没有 `local_symbol` 的按 §15.2 第 3 条处理。
   - A1 不需要旧 `split` 关联列（见 §15.2 第 5 条）。
